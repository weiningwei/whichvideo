# WhichVideo · 以图搜视频

<img src="src/renderer/public/favicon-32.png" width="96" alt="WhichVideo 图标" align="right" />

**看到一张截图，想确认这个画面是不是自己下过的某一集。**

WhichVideo 把导入的视频自动抽帧、建立指纹索引，之后丢进任何一张图（截图 /
海报 / 缩略图 / 屏摄），它会回答三件事：

1. **出自哪个视频** —— 命中的是哪个文件、相似度多少；
2. **出现在第几分几秒** —— 命中时间点精确到秒，**可一键从该位置起播**，直接核对画面；
3. **这个视频是否已在你的库里** —— 命中即说明已下载；此外还能**查重**：
   库里是否已经存了多份相同或高度相似的副本。

纯本地运行，索引与视频信息只存在你自己的磁盘上。

### 隐私

**没有任何数据上传。** 这一点由 `pnpm test:network` 逐项断言，不只是口头承诺：

| 环节 | 是否联网 |
| --- | --- |
| 导入 / 抽帧 / 建索引 | 否 |
| 文件夹监听 | 否 |
| 指纹检索 | 否 |
| 自动更新 | 否（未配置更新源，运行时静默跳过） |
| **粘贴网页链接取图** | **是 —— 仅此一处，且需你主动触发** |

链接取图是唯一出口：只在你点「链接检索」或回车时发起，请求你贴的那个 URL，
**只带固定的 `User-Agent`，不带任何本机标识、不上传任何本地数据**。
除此之外程序不发起任何网络请求（无遥测、无统计、无崩溃上报，依赖里也没有这类库）。

运行期日志（`whichvideo.log`）会记录数据目录的绝对路径，仅写入本地文件，不外发。

**适合谁**：网盘里存了几百集剧、想确认"这集我到底下没下"的人；以及库越攒越大、
想清理重复副本的人。

## 快速开始

需要 node >= 22、pnpm >= 10，以及 **ffmpeg**（抽帧用，见下）。

```bash
# 1. 安装依赖
pnpm install

# 2. 准备 ffmpeg（三选一）
pnpm fetch:ffmpeg              # 联网自动下载（默认，多源回退）
pnpm fetch:ffmpeg --from "<你本机 ffmpeg 的 bin 目录>"   # 复用本机已装的
# 或：把 ffmpeg.exe / ffprobe.exe 手动放进 resources/bin

# 3. 开发模式运行
pnpm dev

# 4. 打包
pnpm build:portable            # 绿色版目录（推荐，无需安装）
pnpm build:win                 # NSIS 安装包
```

`pnpm fetch:ffmpeg` 下载不动时（`gyan.dev` 与 GitHub 在不同网络下差异很大），
脚本已做多源自动回退、有进度与超时、缓存续跑。走代理需要显式设 `HTTPS_PROXY`，
且 Node 24 要加 `NODE_USE_ENV_PROXY=1`；实在不行就用浏览器下好 zip 再
`--from "<zip 路径>"`。完整参数见 [docs/troubleshooting.md](docs/troubleshooting.md)。

## 使用流程

### 1. 建库

| 操作 | 位置 | 说明 |
| --- | --- | --- |
| 导入视频文件 | 顶部「+ 导入视频」 | 可多选；导入后会自动把它所在目录登记为监听目录 |
| 导入文件夹 | 顶部「+ 导入文件夹」 | 递归扫描整棵目录树，并持续监听 |
| 拖入文件夹 | 「视频库与监听」右侧面板 | 直接把资源管理器里的文件夹拖进来 |
| 重新扫描 | 监听面板 / 列表工具栏 | 手动兜底（例如从网络位置恢复后） |

扫描是流式的：边扫描边入库，界面上的进度、视频数量、帧指纹数量实时变化；抽帧与哈希计算在后台并发队列里跑，不阻塞操作。

### 2. 搜图

四种输入方式，任选其一：

- 把图片**拖进窗口**
- **Ctrl+V 粘贴**截图
- 点「选择图片文件」
- **粘贴网页链接**（回车或点「链接检索」）

#### 链接输入

链接支持图片直链与普通网页两种，程序自动判断：

| 链接类型 | 处理方式 |
| --- | --- |
| 图片直链（`https://…/a.jpg`） | 直接下载后检索 |
| 普通网页 | 依次尝试 `og:image` → `twitter:image` → `link[rel=image_src]` → 首个 `<img>` |

只放行 `http:` / `https:`，图片上限 10 MB，超时 15 秒。失败时会说明具体原因
（协议不支持 / 超时 / 体积超限 / 网页里没找到图片）。

#### 看结果

结果按相似度排序，每张卡片给出：

- 相似度百分比 + 结构 / 颜色分项
- **命中时间点**与缩略图 —— 例如「**1:23:45 处播放**」，点它就用
  mpv / PotPlayer / VLC（未安装则系统默认播放器）打开该视频并**跳到这一秒**，
  不用拖进度条找
- `已下载 · 本地库中` 状态、文件时长 / 分辨率 / 体积 / 编码
- 定位文件、重新索引

顶部横幅直接给出结论：命中 → "已在本地库中找到这张图对应的视频"；未命中 → "这张图对应的视频大概率还没下载到已导入的目录里"。

### 3. 键盘快捷键

按 `?` 随时打开快捷键面板（顶栏右上角也有入口）。常用的几个：

| 键 | 作用 |
| --- | --- |
| `↑` `↓` | 上移 / 下移一行，**同时改选中**（与文件管理器一致，分组视图下跳过分组标题） |
| `Shift+↑` `Shift+↓` | 从当前选中处连续扩展选区 |
| `Ctrl+↑` `Ctrl+↓` | 只移动光标，不改已有选区 |
| `Home` `End` / `PgUp` `PgDn` | 跳到首尾 / 翻页 |
| `Enter` | 播放（优先播放第一个选中的，否则光标处） |
| `Space` | 在光标处加选 / 取消选中（不动光标） |
| `Delete` | 从索引库移除选中项（多选时先确认，**不删磁盘文件**） |
| `Ctrl+A` / `Esc` | 全选 / 取消选择 |
| `→` `←` | 展开 / 收起**光标所在**的分组 |
| `1` `2` | 切到图片搜索 / 视频库 |
| `/` | 聚焦视频库的筛选框 |
| `G` / `S` / `B` / `I` | 分组切换 / 重新扫描 / 重建索引 / 导入视频 |
| `Ctrl+L` `Ctrl+R` | 在资源管理器定位 / 重建光标视频的索引 |

输入框聚焦时这些键会暂时让位给文字输入。

### 4. 动态更新

被监听目录（含子目录，初次扫描最深 24 层、监听最深 32 层）里发生以下变化时，索引自动同步：

| 变化 | 行为 |
| --- | --- |
| 新文件出现 | 等文件写入稳定（默认 1.5s）后自动入队、抽帧、入库 |
| 文件被覆盖/修改 | 大小或修改时间变化 → 旧指纹作废、重新抽帧 |
| 文件被删除 | 从索引库移除对应记录与帧指纹 |
| 整个目录被删除 | 该目录下所有视频记录一并清理 |
| 监听被暂停 | 只停止监听，已入库的数据保留 |

暂停 / 恢复 / 移除监听、重新扫描都在右侧监听面板里操作。移除监听**不会**删除磁盘文件。

## 更多能力

### 库内查重

工具栏「**查重**」：扫描全库，把画面高度相似的视频**聚合成组**给出（而不是
罗列一堆两两配对）。

- **相似组**：A、B、C 互相相似时归为**一组**，组内默认建议保留体积最大的，
  其余标「将移除」，一键批量移除（只从索引库移除，**不删磁盘文件**）；
  也可以改点「保留这个」换保留项
- **完全相同文件**：大小与时长一致的组会再算**文件哈希（SHA-256）**校验 ——
  校验一致才标注「完全相同文件」，即 bit 级的同一份副本；哈希不同则不标注，
  交回画面相似度判断
- **相似但非完全相同**的组用**帧覆盖率**判定：取多个时间点逐帧核对，
  帧帧都像才是真重复；只有零星一帧像（同剧不同集的相同场景）会被压低分数，
  减少误报

结果窗口关闭即弃（库内容随时变化，下次查重重新计算）。

### 抽帧采样模式

决定「建索引时怎么挑帧」，直接影响能不能搜到某个画面。可在「索引设置」里
全局选择，也可对**单个视频**单独指定：

| 模式 | 做法 | 适合 |
| --- | --- | --- |
| **均匀采样**（默认） | 按固定间隔取帧 | 索引速度快。镜头较长的素材（访谈、录屏、静态画面） |
| **场景检测** | 先检测镜头切换点，**每个镜头至少一帧**，长镜头内部再补充 | 镜头切换密集的内容（剧集、剪辑片）。召回更高，索引更慢 |

视频列表里每行都有「**采样**」列，显示该视频当前使用的模式：

- 点「均匀 / 场景」选择想要的方式 → 点该行的「**索引**」按新模式重建
- 若方式没变，会提示「已经是 X 采样，无需重建」，不会重复抽帧
- 「索引设置」里切换全局模式后，**跟随全局**的视频会同步显示新模式，
  再点「重建全部索引」即可全库套用（单独指定过模式的视频不受影响）

### 视频列表管理

| 能力 | 说明 |
| --- | --- |
| 筛选 | 按关键字（文件名 / 目录）与状态（已索引 / 待索引 / 索引中 / 失败）过滤 |
| 排序 | 加入时间 / 名称 / 体积 / 时长 |
| 分组 | 按监听文件夹分组、可折叠（`←` `→` 展开收起光标所在组） |
| 多选 | `Shift` 连选、`Ctrl` 点选、`Ctrl+A` 全选、`Space` 加选 |
| 批量 | 重建选中项的索引、从库中移除选中项（不删文件） |
| 缩略图 | 每行显示代表帧缩略图，一眼认出是哪一集 |

### 播放与定位

- 结果卡上的「**XX:XX 处播放**」= 系统默认播放器（或自动寻找的
  mpv / PotPlayer / VLC）打开视频并跳到命中时间点
- 「定位」= 在资源管理器里选中该文件
- 列表行上的「播放 / 定位 / 索引 / 移除」四个操作同理

### 通知

- **状态栏**（底部）显示最近的操作反馈，几秒后自动消失
- 需要留意的问题（**索引失败、主进程异常**等）在**右下角**弹出，按重要程度
  停留 8~12 秒；鼠标**悬停可暂停倒计时**，点击立即关闭

## 便携（绿色）模式

`build:portable` 产出两份目录：`release\WhichVideo-portable\`（仓库内）与
**仓库上一级目录**下的同名文件夹。外面那份是给用户直接双击运行的。

重新打包时，仓库外那份**会保留已有的 `data\`**，索引库不用重建。

数据写在 `exe 同级\data\`：

```
data\
├─ whichvideo.db      索引库（SQLite）
├─ whichvideo.log     运行日志
└─ session\           Chromium 缓存
```

整个文件夹拷走即可迁移。放在只读位置（如 `Program Files`）会自动回退到
`%APPDATA%\WhichVideo`。

可用的环境变量：

| 变量 | 作用 |
| --- | --- |
| `WHICHVIDEO_DATA_DIR` | 指定数据目录，优先级最高 |
| `WHICHVIDEO_FFMPEG` / `WHICHVIDEO_FFPROBE` | 指定 ffmpeg / ffprobe 路径 |
| `WHICHVIDEO_BIN_DIR` | 指定包含二进制的目录 |

## 它是怎么判断的

一句话：**抽帧 → 每帧压成 144 字节指纹 → 搜图时也算一份指纹 → 比对谁更接近。**

| 步骤 | 做法 |
| --- | --- |
| 抽帧 | 按时长分档，1 小时约 240 帧；可选均匀采样或场景检测采样（见上） |
| 指纹 | 9×8 灰度网格 + 16×16 四通道结构 + 4×4×4 颜色直方图，合计 144 字节 |
| 存储 | 全部帧指纹常驻一个连续内存块，搜索是纯位运算 |
| 检索 | 64bit dHash 粗筛 → 512bit 结构距离 + 颜色直方图 → 自适应加权打分 |
| 查询图 | 宽于 320 像素时先缩放到 320 再算指纹（指纹与分辨率无关，只影响速度） |

关键性质（都有自检守着）：

- **指纹与分辨率无关** —— 截图 1920 宽、视频帧 320 宽，缩放后结构距离仍为 0
- **对再压缩极其鲁棒** —— 同一画面改几十个像素值，距离只差 3 bit
- **召回率由帧数决定，不是由算法决定** —— 均匀采样下 1 小时视频每个镜头约 33% 概率被采到，
  这正是「场景检测」采样存在的理由

完整推导、内存布局、实测距离量级见 **[docs/how-search-works.md](docs/how-search-works.md)**。

## 配置项

在「视频库与监听」右侧面板的「索引设置」标签里：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 抽帧采样模式 | 均匀采样 | 均匀 = 按间隔取帧、快；场景检测 = 每个镜头至少一帧、召回更高但更慢（可对单个视频单独指定） |
| 每个视频抽帧数（上限） | 240 | 实际帧数按时长自动分档，这里是封顶值 |
| 并发解码数 | 2 | 机械硬盘建议 1~2，固态可以 3~4 |
| 匹配阈值（%） | 60 | 低于该结构相似度的帧直接丢弃，调低可召回更多弱匹配 |
| 最多返回结果 | 40 | 搜索结果条数上限 |
| 新文件稳定等待（毫秒） | 1500 | 避免把还在复制/下载中的文件入库 |
| 文件被删除时自动从库中移除 | 开 | 关闭后磁盘删了文件，库里仍保留记录 |

> 调大抽帧数**不一定**增加实际帧数：分档表在 1 小时处已封顶 240，设 300 或 400
> 拿到的都是 240。真正决定抽多少帧的是代码里的 `FRAME_COUNT_TABLE`。

## 常见问题

**搜不到明明存在的画面？**
两步：① 确认该视频状态是「已索引」；② 如果素材是镜头切换密集的剧集/剪辑，
把该视频的采样方式切成「场景检测」再点「索引」重建（见 [抽帧采样模式](#抽帧采样模式)）。
最常见的原因是**采样太稀**：一集剧约 720 个镜头，均匀采样 240 帧意味着每个镜头
约 33% 的概率被采到 —— 画面没被索引，搜再多也没用；场景检测能让每个镜头至少
有一帧。截图经过裁剪、加字幕遮挡、强滤镜也会降低命中率，取视频中更完整的一帧
作为查询图会有帮助。

**相似度为什么普遍 70%~80%？**
不同分辨率、不同压缩率的画面本身就会有几十个 bit 的结构差异，属正常范围。
分数梯队（几乎确定 / 高度相似 / 可能匹配 / 弱匹配）比绝对值更有参考意义。

**查重会把「同剧不同集」误判成重复吗？**
比早期的单帧判据好得多：现在的判定是「多帧覆盖率 + SHA-256」两级 ——
只有多个时间点帧帧都像、或文件哈希完全一致才会给出高分组，零星相似会被压分。
但同剧里完全复用的镜头（片头、回忆杀）仍可能进入相似组，移除前建议扫一眼组内
文件名与体积。

**支持哪些格式？**
mp4 / mkv / avi / mov / wmv / flv / webm / m4v / ts / m2ts / mpg / mpeg / rmvb / rm / 3gp，
只要 ffmpeg 能解码即可。

**索引库能有多大？**
每帧指纹 144 字节，1 小时视频 240 帧（约 34KB）。按 1 万个平均 45 分钟的剧集算约
96 万帧、内存索引 132MB；10 万帧量级时 14MB、全量扫描约 20ms。搜索是纯内存位运算，
库再大只是扫描时间线性增长。

**升级后旧索引失效？**
若提示"结构指纹已改为全图等距抽样"，此前只编码了画面上半部分（字幕条、下三分之一
构图会被系统性低估），因此老指纹全部失效，点「重建全部索引」即可。

**双击 exe 没反应 / 打包报 EPERM / 环境类崩溃？**
这些属于打包与运行环境问题，见 **[docs/troubleshooting.md](docs/troubleshooting.md)**。

## 开发

技术栈：Electron + React 19 + Tailwind CSS v4 + better-sqlite3。渲染端产物
`app.asar` 约 3.4MB，其余是 Electron/Chromium 运行时与 ffmpeg。

```bash
pnpm test                # 全部自检
pnpm dev                 # 开发模式
pnpm icon                # 重新生成应用图标
```

路径处理、配色纪律、图标接线、光标与连选行为、渲染端冒烟等）。各套的作用
与单独运行方式见 [AGENTS.md](AGENTS.md)。打包与运行遇到怪问题（双击没反应、
EPERM、Electron 运行时反复下载）见 [docs/troubleshooting.md](docs/troubleshooting.md)。
