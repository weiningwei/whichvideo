# WhichVideo · 以图搜视频

<img src="src/renderer/public/favicon-32.png" width="96" alt="WhichVideo 图标" align="right" />

**看到一张截图，想确认这个画面是不是自己下过的某一集。**

已发布 [**v0.1.0 公开预览版**](https://github.com/weiningwei/whichvideo/releases/tag/v0.1.0)，提供 **Windows x64、macOS（Apple Silicon / Intel）和 Linux x64** 发行资产。当前尚未配置 Windows 代码签名或 Apple 签名/公证，系统可能拦截下载的程序；请从 Releases 下载并在可写目录中运行。

WhichVideo 把导入的视频自动抽帧、建立指纹索引，之后丢进任何一张图（截图 /
海报 / 缩略图 / 屏摄），它会回答三件事：

1. **出自哪个视频** —— 命中的是哪个文件、相似度多少；
2. **出现在第几分几秒** —— 命中时间点精确到秒；检测到 mpv/VLC 等支持定位的播放器时，可从该位置起播，直接核对画面；
3. **这个视频是否已在你的库里** —— 命中即说明已下载；此外还能**查重**：
   库里是否已经存了多份相同或高度相似的副本。

纯本地运行，索引与视频信息只存在你自己的磁盘上。

### 隐私

**本地视频、索引与截图不会上传。** 后端仅在两种明确场景访问网络：

| 环节 | 是否联网 |
| --- | --- |
| 导入 / 抽帧 / 建索引 | 否 |
| 文件夹监听 | 否 |
| 指纹检索 | 否 |
| 启动版本检查 | 是（可在设置关闭；只查询 GitHub Releases） |
| **粘贴网页链接取图** | **是 —— 仅此一处，且需你主动触发** |

链接取图只在你点「搜索」或回车时发起，请求你贴的那个 URL，
**只带固定的 `User-Agent`，不带任何本机标识、不上传任何本地数据**。
除可关闭的版本检查外，程序不发起其他网络请求（无遥测、无统计、无崩溃上报）。

运行期日志（`whichvideo.log`）会记录数据目录的绝对路径，仅写入本地文件，不外发。

**适合谁**：网盘里存了几百集剧、想确认"这集我到底下没下"的人；以及库越攒越大、
想清理重复副本的人。

## 快速开始

普通用户可从 [v0.1.0 Releases](https://github.com/weiningwei/whichvideo/releases/tag/v0.1.0) 下载对应平台的产物：Windows 安装包或便携 ZIP、macOS Apple Silicon / Intel `.app` ZIP、Linux x64 AppImage；无需安装 Node、pnpm 或 Rust。
正式发行资产由 GitHub Actions 从版本标签重新构建，不使用开发者本机的旧产物。
两个版本都不内置 FFmpeg，首次启动可在软件中指定其 `bin` 目录。

如需从源码构建，则需要 Node >= 22、pnpm >= 10、Rust stable、对应平台的 Tauri 系统依赖，
以及 **ffmpeg**（抽帧用，见下）。

```bash
# 1. 安装依赖
pnpm install

# 2. 开发环境准备 ffmpeg（二选一；发布包不内置）
pnpm fetch:ffmpeg              # Windows：下载到 resources/bin，仅供开发与测试
# 或：把 ffmpeg/ffprobe 加入系统 PATH

# 3. 开发模式运行
pnpm dev

# 4. 打包
pnpm build:portable            # Windows 绿色版目录（推荐，无需安装）
pnpm build:portable:fast       # Windows 本机快速绿色版（不用于正式发行）
pnpm build:win                 # Windows NSIS 安装包
pnpm build:mac                 # macOS .app
pnpm build:linux               # Linux AppImage
```

`pnpm build:portable:fast` 专供 Windows 本机反复验证：它把 Rust 构建缓存放进
`src-tauri/target-fast`，使用 Thin LTO、较多 codegen 单元和 release 增量编译。首次运行仍需
编译依赖；之后只改少量 Rust 代码时通常会明显更快。它与正式 `build:portable` 的
`src-tauri/target/release` 缓存完全隔离，产物目录和 `data\` 保留规则相同。

正式测试、提交发布以及 GitHub Actions 仍使用 `pnpm build:portable` 或各平台标准构建命令，
以保持体积优先的完整 LTO 发行配置。Cargo 默认会使用可用 CPU，无需额外设置并行数。

`pnpm fetch:ffmpeg` 下载不动时（`gyan.dev` 与 GitHub 在不同网络下差异很大），
脚本已做多源自动回退、有进度与超时、缓存续跑。走代理需要显式设 `HTTPS_PROXY`，
且 Node 24 要加 `NODE_USE_ENV_PROXY=1`；实在不行就用浏览器下好 zip 再
`--from "<zip 路径>"`。完整参数见 [docs/troubleshooting.md](docs/troubleshooting.md)。
macOS/Linux 请用系统包管理器安装 FFmpeg，或在软件中手动指定其 `bin` 目录；内置下载源只有 Windows 版本。

正式版不内置 FFmpeg。首次启动会依次检查环境变量、上次手动设置的目录和系统 PATH；
仍未找到时会提示选择同时包含 `ffmpeg` 与 `ffprobe`（Windows 为 `.exe`）的 `bin` 目录。选择结果保存在
应用数据目录中，也可随时在「索引设置 → 媒体工具」里更换。

## 使用流程

### 1. 建库

| 操作 | 位置 | 说明 |
| --- | --- | --- |
| 导入视频文件 | 视频库「添加 → 视频文件」 | 可多选；仅导入所选文件，不监视所在目录 |
| 一次性导入文件夹 | 视频库「添加 → 导入文件夹」 | 保留文件夹层级并递归扫描当前视频，不持续监视后续变化 |
| 持续监视文件夹 | 视频库「添加 → 监视文件夹」 | 首次递归扫描，并自动同步后续新增、修改与删除 |
| 拖入文件夹 | 「管理文件夹」抽屉 | 等同于「监视文件夹」 |
| 重新扫描 | 视频库「更多 → 重新扫描」 | 手动兜底（例如从网络位置恢复后） |

导入后默认进入「文件夹」视图：先看到文件夹，点击可逐层展开子目录和视频；「全部视频」可切回平铺列表。搜索或状态筛选时会展开匹配目录，也可以单独收起。一次性导入与监视导入都保留目录归属，只有后者自动同步磁盘变化。

扫描是流式的：边扫描边入库，界面上的进度、视频数量、帧指纹数量实时变化；抽帧与哈希计算在后台并发队列里跑，不阻塞操作。

### 2. 搜图

四种输入方式，任选其一：

- 把图片**拖进窗口**
- **Ctrl+V 粘贴**截图
- 点「选择图片」
- **粘贴网页链接**（回车或点「搜索」）

#### 链接输入

链接支持图片直链与普通网页两种，程序自动判断：

| 链接类型 | 处理方式 |
| --- | --- |
| 图片直链（`https://…/a.jpg`） | 直接下载后检索 |
| 普通网页 | 依次尝试 `og:image` → `twitter:image` → `link[rel=image_src]` → 首个 `<img>` |

只放行 `http:` / `https:`，图片上限 10 MB，超时 15 秒。失败时会说明具体原因
（协议不支持 / 超时 / 体积超限 / 网页里没找到图片）。

#### 看结果

结果按相似度排序，每张卡片给出：

- 视频文件名和所在目录；同名视频可通过目录区分
- 相似度百分比 + 结构 / 颜色分项
- **命中时间点**与缩略图 —— 例如「**1:23:45 处播放**」，点它就用
  mpv / PotPlayer / VLC（未安装则系统默认播放器）打开该视频并**跳到这一秒**，
  不用拖进度条找
- `已下载 · 本地库中` 状态、文件时长 / 分辨率 / 体积 / 编码
- 定位文件；未完成或失败的索引可从结果卡重新索引

顶部横幅直接给出简短结论：命中显示「找到了」和最佳匹配；未命中显示
「没有找到相似画面」。清除或开始新搜索后，旧结果不会冒充本次结果。

### 3. 键盘快捷键

按 `?` 随时打开快捷键面板（顶栏右上角也有入口）。常用的几个：

| 键 | 作用 |
| --- | --- |
| `↑` `↓` | 在已展开的视频行间移动，同时改选中 |
| `Shift+↑` `Shift+↓` | 从当前选中处连续扩展选区 |
| `Ctrl+↑` `Ctrl+↓` | 只移动光标，不改已有选区 |
| `Home` `End` / `PgUp` `PgDn` | 跳到首尾 / 翻页 |
| `Enter` | 播放（优先播放第一个选中的，否则光标处） |
| `Space` | 在光标处加选 / 取消选中（不动光标） |
| `Delete` | 从索引库移除选中项（多选时先确认，**不删磁盘文件**） |
| `Ctrl+A` / `Esc` | 全选 / 取消选择 |
| `→` `←` | 文件夹按钮有焦点时展开 / 收起该文件夹 |
| `1` `2` | 切到图片搜索 / 视频库 |
| `/` | 聚焦视频库的筛选框 |
| `G` / `S` / `B` / `I` | 文件夹与全部视频切换 / 重新扫描 / 重建索引 / 导入视频 |
| `Ctrl+L` `Ctrl+R` | 在资源管理器定位 / 重建光标视频的索引 |

输入框聚焦时这些键会暂时让位给文字输入。

### 4. 动态更新

只有明确选择「监视文件夹」或拖入监听面板的目录，才会自动监视。被监听目录
（含子目录，初次扫描最深 24 层、监听最深 32 层）里发生以下变化时，索引自动同步：

| 变化 | 行为 |
| --- | --- |
| 新文件出现 | 等文件写入稳定（默认 1.5s）后自动入队、抽帧、入库 |
| 文件被覆盖/修改 | 大小或修改时间变化 → 旧指纹作废、重新抽帧 |
| 文件被删除 | 从索引库移除对应记录与帧指纹 |
| 整个目录被删除 | 该目录下所有视频记录一并清理 |
| 监听被暂停 | 只停止监听，已入库的数据保留 |

暂停 / 恢复监听、单目录重新扫描都在「管理文件夹」抽屉里操作。「从库中移除」会移除该文件夹及其关联的视频索引，**不会**删除磁盘文件；另行导入的视频不受影响。

## 更多能力

### 库内查重

视频库右上角「**更多操作 → 查找重复视频**」：扫描全库，把画面高度相似的
视频**聚合成组**给出（而不是罗列一堆两两配对）。

- **相似组**：A、B、C 互相相似时归为**一组**，组内默认建议保留体积最大的，
  其余标「将移除」，一键批量移除（只从索引库移除，**不删磁盘文件**）；
  也可以改点「保留这个」换保留项
- **完全相同文件**：大小与时长一致的组会再算**文件哈希（SHA-256）**校验 ——
  校验一致才标注「完全相同文件」，即 bit 级的同一份副本；哈希不同则不标注，
  交回画面相似度判断
- **相似但非完全相同**的组用**帧覆盖率**判定：取多个时间点逐帧核对，
  帧帧都像才是真重复；只有零星一帧像（同剧不同集的相同场景）会被压低分数，
  减少误报

组内每个视频都显示文件名和所在目录，重名时先核对目录再决定保留项；确认移除时
会显示保留文件的完整路径。移除成功后结果才会更新，失败会提示原因。结果窗口
关闭即弃（库内容随时变化，下次查重重新计算）。

### 抽帧采样模式

决定「建索引时怎么挑帧」，直接影响能不能搜到某个画面。可在「索引设置」里
全局选择，也可对**单个视频**单独指定：

| 模式 | 做法 | 适合 |
| --- | --- | --- |
| **均匀采样**（默认） | 按固定间隔取帧 | 索引速度快。镜头较长的素材（访谈、录屏、静态画面） |
| **场景检测** | 优先取镜头切换点，有余量时补长镜头内部帧；始终受抽帧数上限约束 | 镜头切换密集的内容（剧集、剪辑片）。召回通常更高，索引更慢 |

视频行的「更多操作」里可选「按场景/均匀模式重建」或「重新索引」；重建会按所选
模式重新抽帧，即使模式没变也会执行。「索引设置」里切换全局模式不会自动重建
已有索引：仍跟随旧全局模式的视频会更新采样设置，重建后才按新模式抽帧；显式
指定其他模式的视频不受影响。

### 视频列表管理

| 能力 | 说明 |
| --- | --- |
| 筛选 | 按关键字（文件名 / 目录）与状态（已索引 / 待索引 / 索引中 / 失败）过滤 |
| 排序 | 加入时间 / 名称 / 体积 / 时长 |
| 文件夹视图 | 只有导入的目录形成可展开文件夹；单独导入的视频直接显示在顶层 |
| 全部视频 | 不按目录折叠，按当前排序展示所有视频 |
| 多选 | 点击整行选中，`Shift` 连选、`Ctrl` 点选；工具栏「全选」或 `Ctrl+A` 选择当前已展开的视频 |
| 批量 | 重建选中项的索引、从库中移除选中项（不删文件；失败时不会提前清空选择） |
| 缩略图 | 每行显示代表帧缩略图，一眼认出是哪一集 |

### 播放与定位

- 结果卡上的「**XX:XX 处播放**」= 系统默认播放器（或自动寻找的
  mpv / PotPlayer / VLC）打开视频并跳到命中时间点
- 「定位」= 在资源管理器里选中该文件
- 视频行直接提供「播放」和「更多操作」；定位文件、查看索引帧、重建索引及从库中移除都在更多菜单中

### 通知

- **状态栏**（底部）持续显示当前任务状态：空闲、索引进度、正在处理的文件，或最近一次索引失败
- **右下角通知**用于一次性结果和需要留意的问题（导入完成、保存设置、索引失败、后端异常等）；
  会按重要程度停留 5~12 秒，鼠标**悬停可暂停倒计时**，点击立即关闭

## 数据目录与便携（绿色）模式

Windows 的 `build:portable` 产出两份目录：`dist\WhichVideo-portable\`（仓库内）与
**仓库上一级目录**下的同名文件夹。外面那份是给用户直接双击运行的。

重新打包时，仓库外那份**会保留已有的 `data\`**，索引库不用重建。

**所有版本**把数据写在程序同级的 `data` 目录（Windows 是 exe 同级，macOS 是 `.app` 同级，Linux 是 AppImage 同级）：

```
data\
├─ whichvideo.db      索引库（SQLite）
├─ whichvideo.log     运行日志
├─ frames\            索引帧
└─ session\           WebView 缓存
```

整个程序目录拷走即可迁移。程序不会回退到用户目录；如果程序目录不可写，启动会明确失败，
因此请安装到当前用户可写的位置。macOS 不要直接放在普通用户无写权限的 `/Applications`；Linux AppImage 也请放在可写目录。Windows 卸载程序默认保留未知的 `data\` 目录，但卸载或手工删除前仍建议备份。
从旧版本首次启动时，如果新目录还没有对应文件，会把原用户目录中的索引库和索引帧复制进来。

可用的环境变量：

| 变量 | 作用 |
| --- | --- |
| `WHICHVIDEO_DATA_DIR` | 指定数据目录，优先级最高 |
| `WHICHVIDEO_FFMPEG` / `WHICHVIDEO_FFPROBE` | 指定 ffmpeg / ffprobe 路径 |
| `WHICHVIDEO_BIN_DIR` | 指定包含二进制的目录 |

FFmpeg 探测优先级：`WHICHVIDEO_FFMPEG` + `WHICHVIDEO_FFPROBE` → `WHICHVIDEO_BIN_DIR`
→ 软件内手动设置的目录 → 系统 `PATH` → macOS 常见 Homebrew 目录。显式路径必须同时提供 `ffmpeg` 与 `ffprobe`，避免混用不同版本。

## 它是怎么判断的

一句话：**抽帧 → 每帧压成 256 字节指纹 → 搜图时也算一份指纹 → 比对谁更接近。**

| 步骤 | 做法 |
| --- | --- |
| 抽帧 | 按时长分档，1 小时约 240 帧；可选均匀采样或场景检测采样（见上） |
| 指纹 | 9×8 灰度网格 + 16×16 四通道结构 + 4×4×4 颜色直方图 + 4×4 空间布局，合计 256 字节 |
| 存储 | 全部帧指纹常驻一个连续内存块，搜索是纯位运算 |
| 检索 | 64bit dHash 粗筛 → 1024bit 结构距离 + 颜色直方图 → 自适应加权打分 |
| 查询图 | 宽于 320 像素时先缩放到 320 再算指纹（指纹与分辨率无关，只影响速度） |

关键性质（都有自检守着）：

- **指纹与分辨率无关** —— 截图 1920 宽、视频帧 320 宽，缩放后结构距离仍为 0
- **对再压缩极其鲁棒** —— 同一画面改几十个像素值，距离只差几十 bit
- **召回率由帧数决定，不是由算法决定** —— 均匀采样下 1 小时视频每个镜头约 33% 概率被采到，
  这正是「场景检测」采样存在的理由

完整推导、内存布局、实测距离量级见 **[docs/how-search-works.md](docs/how-search-works.md)**。

## 配置项

在视频库右上角的「索引设置」抽屉里：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| FFmpeg 目录 | 自动检测 | 未加入 PATH 时，可选择同时包含 ffmpeg 与 ffprobe 的 bin 目录 |
| 抽帧采样模式 | 均匀采样 | 均匀 = 按间隔取帧、快；场景检测 = 优先覆盖镜头切换点、通常召回更高但更慢（可对单个视频单独指定） |
| 每个视频抽帧数（上限） | 240 | 实际帧数按时长自动分档，这里是封顶值 |
| 并发解码数 | 2 | 机械硬盘建议 1~2，固态可以 3~4 |
| 匹配阈值（%） | 60 | 低于该结构相似度的帧直接丢弃，调低可召回更多弱匹配 |
| 最多返回结果 | 40 | 搜索结果条数上限 |
| 新文件稳定等待（毫秒） | 1500 | 避免把还在复制/下载中的文件入库 |
| 文件被删除时自动从库中移除 | 开 | 关闭后磁盘删了文件，库里仍保留记录 |

> 调大抽帧数**不一定**增加实际帧数：分档表在 1 小时处已封顶 240，设 300 或 400
> 拿到的都是 240。真正决定抽多少帧的是代码里的 `FRAME_COUNT_TABLE`。

## 常见问题

**搜不到明明存在的画面？**
两步：① 确认该视频状态是「已索引」；② 如果素材是镜头切换密集的剧集/剪辑，
在该视频的「更多操作」里选择「按场景模式重建」（见 [抽帧采样模式](#抽帧采样模式)）。
最常见的原因是**采样太稀**：一集剧约 720 个镜头，均匀采样 240 帧意味着每个镜头
约 33% 的概率被采到 —— 画面没被索引，搜再多也没用；场景检测能优先覆盖镜头切换点，
但镜头数超过抽帧上限时无法保证每个镜头都有一帧。截图经过裁剪、加字幕遮挡、
强滤镜也会降低命中率，取视频中更完整的一帧
作为查询图会有帮助。

**相似度为什么普遍 70%~80%？**
不同分辨率、不同压缩率的画面本身就会有几十个 bit 的结构差异，属正常范围。
分数梯队（几乎确定 / 高度相似 / 可能匹配 / 弱匹配）比绝对值更有参考意义。

**查重会把「同剧不同集」误判成重复吗？**
比早期的单帧判据好得多：现在的判定是「多帧覆盖率 + SHA-256」两级 ——
只有多个时间点帧帧都像、或文件哈希完全一致才会给出高分组，零星相似会被压分。
但同剧里完全复用的镜头（片头、回忆杀）仍可能进入相似组，移除前建议扫一眼组内
文件名、所在目录与体积。

**支持哪些格式？**
mp4 / mkv / avi / mov / wmv / flv / webm / m4v / ts / m2ts / mpg / mpeg / rmvb / rm / 3gp，
只要 ffmpeg 能解码即可。

**索引库能有多大？**
每帧指纹 256 字节，1 小时视频 240 帧（约 60KB）。按 1 万个平均 45 分钟的剧集算约
96 万帧、内存索引 246MB；10 万帧量级时 26MB、全量扫描约 20ms。搜索是纯内存位运算，
库再大只是扫描时间线性增长。

**升级后旧索引失效？**
帧指纹带版本号（`FRAME_FORMAT_VERSION`），指纹布局变更时 +1。这次结构指纹从 512bit
扩到 1024bit、每帧从 144 字节变 256 字节，版本号 +1；启动时发现旧版本会自动清空
旧指纹、把视频标回「待索引」并在后台自动重抽，无需手动操作。

**遇到索引或搜索问题，怎样提供诊断信息？**
在「索引设置」抽屉点击「导出诊断包」，选择保存位置即可生成 ZIP。它包含版本、系统、
FFmpeg 探测、资料库汇总、索引状态及索引设置；**不包含日志、视频、缩略图、数据库、
文件名、视频/文件夹路径或 FFmpeg 实际位置**。文件名带 UTC 时间戳，导出后会打开保存目录。
反馈时附上该 ZIP，并说明复现步骤和视频格式即可。

**双击 exe 没反应 / 打包报 EPERM / 环境类崩溃？**
这些属于打包与运行环境问题，见 **[docs/troubleshooting.md](docs/troubleshooting.md)**。

pnpm test                # 全部自检
